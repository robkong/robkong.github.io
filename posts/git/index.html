基本操作
#

仓库（Repository），可以理解成一个目录。这个目录里面的所有文件都被 Git 管理起来，每个文件的修改、删除，Git 都能跟踪或者还原。

选择一个合适的地方，创建一个空目录：

1# 创建一个空目录
2$ mkdir learngit
3
4# 进入目录
5$ cd learngit/

git init——初始化仓库
#

通过 git init 命令，把这个目录变成可以管理的仓库：

1# 初始化仓库
2$ git init
3Initialized empty Git repository in D:/Workspace/GitWorks/learngit/.git/

初始化一个空的仓库（empty Git repository），在当前目录下出现了一个 .git 的目录，这个目录是 Git 用来跟踪管理仓库的。

git status——查看仓库状态
#

通过 git status 命令，查看工作树和仓库在被操作过程中的当前状态。

1$ git status
2On branch main
3
4No commits yet
5
6nothing to commit (create/copy files and use "git add" to track)

解释说明：

On branch main ：当前正处于 main 分支下。

No commits yet ：还没有提交的内容。所谓提交（commit）是指 “记录工作树中所有文件的当前状态”。

nothing to commit (create/copy files and use "git add" to track)：尚没有可提交的内容。

创建一个文件

在learngit 目录下（或者子目录）， 创建一个 README.md 文件

 1# 使用命令创建
 2$ touch README.md
 3
 4# 查看当前状态
 5$ git status
 6On branch main
 7
 8No commits yet
 9
10Untracked files:
11  (use "git add <file>..." to include in what will be committed)
12        README.md
13
14nothing added to commit but untracked files present (use "git add" to track)

可以看到在 Untracked files 中显示了 README.md 文件。只要对 Git 的工作树或仓库进行了操作，git status 命令就会发生变化。

git add——将文件添加到暂存区
#

如果只是在工作树中创建了文件，那么该文件并不会被 Git 跟踪。因此用 git status 命令查看 README.md 文件时，会显示在 Untracked files 中。

要想让文件成为 Git 仓库的管理对象，需要用 git add 命令，将其加入暂存区（Stage 或者 Index）中。暂存区是提交之前的一个临时区域。

通过 git add 命令，把文件添加到暂存区：

 1# 将 README.md 文件提交到暂存区
 2$ git add README.md
 3
 4# 查看当前状态
 5$ git status
 6On branch main
 7
 8No commits yet
 9
10Changes to be committed:
11  (use "git rm --cached <file>..." to unstage)
12        new file:   README.md

将 README.me 文件加入暂存区后，通过 git status 命令查看当前状态发生了变化，显示 README.md 文件出现在了 Changes to be committed 中。

git commit——将文件提交到仓库
#

git commit 命令，可以将当前暂存区中的文件提交到仓库的历史记录中。通过这些记录，可以在工作树中恢复文件。

记述一行提交信息

通过 git commit -m "描述信息"命令，一行提交。

1# 把 README.md 文件提交到仓库
2$ git commit -m "First commit"
3[main (root-commit) 0fb089f] First commit
4 1 file changed, 0 insertions(+), 0 deletions(-)
5 create mode 100644 README.md

解释：

-m 参数后的 “First commit” 称为提交信息，是对这个提交的概述。

1 file changed, 1 insertion(+)：1 个文件被改动，插入了 1 行内容。

记述详细提交信息

通过 git commit 命令，详细提交。

 1$ git commit
 2
 3# 执行后编辑器就会启动，并显示如下结果：
 4
 5# Please enter the commit message for your changes. Lines starting
 6# with '#' will be ignored, and an empty message aborts the commit.
 7#
 8# On branch main
 9#
10# Initial commit
11#
12# Changes to be committed:
13#       new file:   README.md
14#

在编辑器中提交信息的格式如下：

  • 第一行：用一行文字描述提交的更改内容
  • 第二行：空行
  • 第三行以后：记述更改的原因和详细内容

以 # （井号）标为注释的行不用删除。

中止提交

如果在编辑器启动后想中止提交，将提交信息留空，并直接关闭编译器，随后提交就会被中止。

查看提交后的状态

1$ git status
2On branch main
3nothing to commit, working tree clean

显示这是一个干净的工作树。

git log——查看提交的日志
#

git log 命令，查看往仓库中提交的日志。

1$ git log
2commit 1c43e2aa397ce491a350674d69eb0bc07b11eac6 (HEAD -> main)
3Author: robkong <robkong520@gmail.com>
4Date:   Wed Mar 11 13:14:21 2026 +0800
5
6    First commit

解释说明：

commit 旁边的 “1c43e2a…” 是指向这个提交的哈希值。在 GIt 的其它命令中，在指向提交时会用到这个哈希值。

Author 后面显示的是用户信息，给 Git 设置的用户名和邮箱地址。

Date 显示提交执行的日期和事件。再往下就是该提交的描述信息。

显示一行提交的信息

1# 简写
2$ git log --oneline
31c43e2a (HEAD -> main) First commit
4
5# 完整写法
6$ git log --pretty=oneline

显示指定目录、文件的日志

在 git log 命令后加上目录名，便会显示该目录下的日志。如果加的是文件名，就会显示该文件的相关日志。

1$ git log README.md
2commit 1c43e2aa397ce491a350674d69eb0bc07b11eac6 (HEAD -> main)
3Author: robkong <robkong520@gmail.com>
4Date:   Wed Mar 11 13:14:21 2026 +0800
5
6    First commit

显示文件的改动

如果向查看提交所带来的改动，可以加上 -p 参数，文件的前后差别就会显示在提交的信息之后。

1$ git log -p

例如：只查看 README.md 文件的提交日志以及提交前后的差别。

1$ git log -p README.md

分支操作
#

在进行多个并行作业时，会用到分支。在这类并行开发的过程中，往往同时存在多个最新代码状态。

如下所示，从 main 分支创建 feature-A 和 fix-B 分支后，每个分支中都拥有自己的最新代码。

main 分支是目前 Git 默认创建的分支，以前是 master。因此基本上所有的开发都是以 main 这个分支为中心进行的。

不同分支中，可以同时进行完全不同的作业。等该分支的作业完成之后再与 main 分支合并。 比如 feature-A 分支的作业结束后与 main 分支合并，如下所示：

git branch——显示分支一览表
#

git branch 命令，可以将分支列表显示，同时可以确认当前所在分支。

1$ git branch
2* main

可以看到 main 分支左侧标有 “*” （星号），表示这是当前所在的分支。结果中没有显示其它分支名，表示本地仓库中只存在 main 一个分支。

git switch——创建、切换分支
#

如果想以当前的 main 分支为基础创建新的分支，需要用到 git switch -c 命令。

创建并切换到 feature-A 分支并进行提交

1$ git switch -c feature-A
2Switched to a new branch 'feature-A'
3
4# 或者使用以前的命令 git checkout -b <new-branch-name>

这时再来查看分支列表，会显示处于 feature-A 分支下。

1$ git branch
2* feature-A
3  main

feature-A 分支左侧标有 “*”，表示当前分支为 feature-A。在这个状态下像正常开发那样修改代码、执行 git add 命令并进行提交的话，代码就会提交到 feature-A 分支。

实际操作，在 README.me 文件中添加一行。

1# 编辑 README.md 文件
2$ vim README.md
3
4# 按 i ，添加如下内容
5- feature-A
6
7# 按 esc :wq 保存退出

提交到仓库

1$ git add README.md
2$ git commit -m "Add feature-A"
3[feature-A d22bdf0] Add feature-A
4 1 file changed, 2 insertions(+)

于是，这一行就添加到 feature-A 分支中了。

切换到 main 分支

现在看看 main 分支有没有收到影响。首先切换至 main 分支。

1$ git switch main
2Switched to branch 'main'

然后查看 README.md 文件，使用 cat README.md 命令，会发现 README.md 文件仍然保持原先的状态，并没有被添加文字。feature-A 分支的更改不会影响到 main 分支，这正是在开发中创建分支的优点。只要创建多个分支，就可以在不互相影响的情况下同时进行多个功能的开发。

切换回上一个分支

切回到 feature-A 分支。

1$ git switch -
2Switched to branch 'feature-A'

像上面这样用 “-” （连字符）代替分支名，就可以切换至上一个分支。当前，将 “-” 替换成 feature-A 同样可以切换到 feature-A 分支。

特性分支
#

Git 与 Subversion（SVN）等集中型版本管理系统不同，创建分支时 不需要连接中央仓库，所以能够相对轻松地创建分支。因此，当今大部 分工作流程中都用到了特性（Topic）分支。 特性分支顾名思义，是集中实现单一特性（主题）除此之外不进 行任何作业的分支。在日常开发中，往往会创建数个特性分支，同时在 此之外再保留一个随时可以发布软件的稳定分支。稳定分支的角色通常 由 main 分支担当。

之前我们创建了 feature-A 分支，这一分支主要实现 feature-A，除 feature-A 的实现之外不进行任何作业。即便在开发过程中发现了 BUG，也需要再创建新的分支，在新分支中进行修正。

基于特定主题的作业在特性分支中进行，主题完成后再与 main 分支合并。只要保持这样一个开发流程，就能保证 main 分支可以随时供人查看。这样一来，其它开发者也可以放心大胆地从 main 分支创建新的特性分支。

主干分支
#

主干分支是刚才我们讲解的特性分支的原点，同时也是合并的终 点。通常人们会用 main 分支作为主干分支。主干分支中并没有开发到一半的代码，可以随时供他人查看。

有时我们需要让这个主干分支总是配置在正式环境中，有时又需要 用标签 Tag 等创建版本信息，同时管理多个版本发布。拥有多个版本发布时，主干分支也有多个。

git merge——合并分支
#

假设 feature-A 已经实现完毕，想要将它合并到主干分支 main 中。首先切换到 main 分支。

1$ git switch main
2Switched to branch 'main'

然后合并 feature-A 分支。为了在历史记录中明确记录下本次分支合并，需要创建合并提交。因此，在合并时加上 --no-ff 参数。

1$ git merge --no-ff feature-A

随后编辑器会启动，用于录入合并提交的信息。默认信息中已经包含了是从 feature-A 分支合并过来的相关内容，所以不用做任何更改。将编辑器中显示的内容保存，关闭编辑器，然后就会看到如下结果：

1Merge branch 'feature-A'
2
3Merge made by the 'ort' strategy.
4 README.md | 2 ++
5 1 file changed, 2 insertions(+)

这样一来，feature-A 分支的内容就合并到 main 分支中了。

更改提交的操作
#

git reset——回溯历史版本
#

通过上面学习的操作，我们已经学会了如何在实现功能后进行提交，累积提交日志作为历史记录。

Git 的另一特征便是可以灵活操作历史版本。借助分散仓库的优势，可以在不影响其它仓库的前提下对历史版本进行操作。

为了熟悉对历史版本的操作，我们先回溯历史版本，创建一个名为 fix-B 的特性分支。

回溯到创建 feature-A 分支前

让我们先回溯到 feature -A 分支创建之前，创建一个名为 fix-B 的特性分支。

要让仓库的 HEAD、暂存区、当前工作树回溯到指定状态，需要用 git reset --hard 命令。只要提供目标时间点的哈希值，就可以完全恢复至该时间点的状态。

1$ git reset --hard 94ef184f06362a4c5b37db38deae0ab2e83fd7c8
2HEAD is now at 94ef184 增加目前学习的内容

现在已经成功回溯到特性分支（feature-A）创建之前的状态。由于 所有文件都回溯到了指定哈希值对应的时间点上，README.md 文件的 内容也恢复到了当时的状态。

创建 fix-B 分支

1$ git switch -c fix-B
2Switched to a new branch 'fix-B'

在 README.md 文件中添加一行文字。

1- fix-B

然后提交 README.md 文件

1$ git add README.md
2$ git commit -m "Fix B"

#

推送至远程仓库
#

Git 是分布式版本管理系统。上面所学习的，都是针对本地仓库的操作。下面，将学习远程仓库。

在 GitHub 上新建一个仓库。为防止与其他仓库混淆，仓库名请与本地仓库保持一致。即 learngit。

创建时不要选择 Add README 选项（如下图所示），因为一旦勾 选该选项，GitHub 一侧的仓库就会自动生成 README 文件，从创建之 初便与本地仓库失去了整合性。虽然到时也可以强制覆盖，但为防止这 一情况发生还是建议不要勾选该选项，直接点击 Create repository 创建 仓库。

git remote add——添加远程仓库
#

在 GitHub 上创建的仓库路径为“git@github.com:用户名 /learngit.git”。现在我们用 git remote add 命令将它设置成本地仓库的远程仓库。

1$ git remote add origin git@github.com:robkong/learngit.git

远程仓库的名称设置为 origin（标识符）。

git push——推送至远程仓库
#

推送至 main 分支

如果想将当前分支下本地仓库中的内容推送给远程仓库，需要用到 git push命令。

 1$ git push -u origin main

 3Counting objects: 100% (20/20), done.

 5Compressing objects: 100% (13/13), done.
 6Writing objects: 100% (20/20), 1.65 KiB | 423.00 KiB/s, done.
 7Total 20 (delta 7), reused 0 (delta 0), pack-reused 0 (from 0)

 9To github.com:robkong/git-lianxi.git
10 * [new branch]      main -> main
11branch 'main' set up to track 'origin/main'.

像这样执行 git push命令，当前分支的内容就会被推送给远程仓库 origin 的 main 分支。

-u参数可以在推送的同时，将 origin 仓库的 main 分支设置为本地仓库当前分支的 upstream（上游）。添加了这个参数，将来运行 git pull 命令从远程仓库获取内容时，本地仓库的这个分支就可以直接从 origin 的 main 分支获取内容，省去了另外添加参数的麻烦。

执行该操作后，当前本地仓库 main 分支的内容将会被推送到 GitHub 的远程仓库中。在 GitHub 上也可以确认远程 main 分支的内容和本地 main 分支相同。

除了 main 分支之外，远程仓库也可以创建其他分支。举个例子，我们在本地仓库中创建 feature-D 分支，并将它以同名形式 push 至远程仓库。

1$ git switch -c feature-D

从远程仓库获取
#

上面我们把在 GitHub 上新建的仓库设置成了远程仓库，并向这个仓库 push 了 feature-D 分支。现在，所有能够访问这个远程仓库的 人都可以获取 feature-D 分支并加以修改。

现在我们从实际开发者的角度出发，在另一个目录下新建一个本地仓库，学习从远程仓库获取内容的相关操作。这就相当于我们刚刚执行过 push 操作的目标仓库又有了另一名新开发者来共同开发。

1$ git switch -c feature-D origin/feature-D

git pull——获取最新的远程仓库分支
#

现在我们回到原先的那个目录下。这边的本地仓库中只创建了 feature-D 分支，并没有在 feature-D 分支中进行任何提交。然而远程仓库的 feature-D 分支中已经有了我们刚刚推送的提交。这时我们就可以使用 git pull 命令，将本地的 feature-D 分支更新到最新状态。当前分支为 feature-D 分支。

GitHub 端远程仓库中的 feature-D 分支是最新状态，所以本地仓库中的 feature-D 分支就得到了更新。今后只需要像平常一样在本地进行提交再 push 给远程仓库，就可以与其他开发者同时在同一个分支中进行作业，不断给 feature-D 增加新功能。

如果两人同时修改了同一部分的源代码，push 时就很容易发生冲突。所以多名开发者在同一个分支中进行作业时，为减少冲突情况的发生，建议更频繁地进行 push 和 pull 操作。

Github
#

前往 【GitHub 官网 】注册一个账号，就可以免费获得 Git 远程仓库。

创建秘钥
#

第一步：创建 SSH Key 秘钥

1$ ssh-keygen -t rsa -C "youremail@example.com"

把邮件地址换成自己的邮件地址，然后一直回车，使用默认值即可。

顺利的话，在用户主目录里找到 .ssh 目录，里面有 id_rsa 和 id_rsa.pub 两个文件。

其中id_rsa 是私钥，不能泄露出去；id_rsa_pub 是公钥，可以公开。

第二步：将公钥添加到 Github 中

  1. 在 GitHub 网站，右上角点击头像——> 选择 Settings
  2. 左侧选择 SSH and GPG keys
  3. 点击 New SSH key 按钮添加
  4. 在 Title文本框中，为新密钥添加描述性标签
  5. 在 Key 文本框中，粘贴id_rsa.pub文件的内容
  6. 点击 Add SSH key 按钮完成添加
  7. 需确认身份验证才能成功添加

添加远程库
#

在本地创建了一个 Git 仓库，又在 GitHub 创建一个 Git 仓库，让这两个仓库进行远程同步。

GitHub 创建仓库

  1. 在 GitHub 网站右上角点击 +，选择 New repository（或导航到你的个人或组织页面并选择 New）。
  2. 输入仓库名称（必须唯一）
  3. 可选的描述
  4. 并选择可见性：Public（公开）或 Private（私有）。
  5. 可选项：
    • 初始化仓库时添加 README、选择许可证（LICENSE）或添加 .gitignore 模板。
    • 根据需要启用 Issues、Wikis 等功能（可在创建后修改仓库设置）。
  6. 点击 Create repository 完成创建。

从 GitHub 上克隆仓库，并推送：

 1# 克隆仓库
 2$ git clone git@github.com:robkong/learngit.git
 3
 4# 进入目录
 5$ cd learngit/
 6
 7# 创建 README.md 文件
 8echo "# learngit" >> README.md
 9
10# 添加到暂存区
11git add README.md
12
13# 提交到本地仓库
14git commit -m "Add README.md"
15
16# 推送到远程仓库
17git push -u origin main

从本地仓库直接关联远程仓库，并推送

1# 关联远程仓库
2git remote add origin git@github.com:robkong/learngit.git
3
4# 切换到主分支
5git branch -M main
6
7# 推送到远程仓库（第一次携带 -u 参数，之后可以省略）
8git push -u origin main

删除远程库
#

如果添加的时候地址写错了，或者想删除远程库，可以用 git remote rm <name> 命令。建议先用 git remote -v 查看远程库信息：

1# 查看远程库信息
2$ git remote -v
3origin  git@github.com:robkong/learngit.git (fetch)
4origin  git@github.com:robkong/learngit.git (push)

根据名字删除，例如：origin

1$ git remote rm origin
